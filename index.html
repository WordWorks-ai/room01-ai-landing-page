What it is

Room01 is the client experience. Room0 is the platform underneath. Together, they aim to make powerful agents safer to run — without killing usefulness.

Always-on appliance

A dedicated Mac mini you plug in and leave running 24/7.

Message-first interface

Use the channels you already live in. No “assistant app” required.

Governed tool access

Policies + receipts live in room0 — so you can inspect and revoke.

Room0: authority substrate for autonomous systems

Room0 is intentionally boring. It’s where the rules live — and where tool access is enforced. The goal: fail closed by default, with clear boundaries.

Room01 sits inside Room0

Room01 handles messaging, routing, and the user experience. Room0 handles policy, tool gateway, receipts, and governance.

How it works

A simple contract: intent is visible, access is scoped, and actions leave receipts.

1
You message Room01

“Draft this.” “Schedule that.” “Monitor this.” “Summarize that.”

2
The agent proposes an action

Room01 makes the plan and tool requests explicit: what it wants to do, and why.

3
Room0 enforces policy

Ask / allow / block — and produce a receipt you can audit later.

FAQ

Is this a product I can buy today?

No — this is a vision-stage experiment. If it becomes real, early collaborators and build-list folks will hear first.

Do I need to install a new app?

The intention is no. Room01 is message-first. An admin console exists for advanced configuration — optional.

What’s the difference between room0 and room01?

room0 is the governance kernel (policy, tool gateway, receipts). room01 is the client experience running on top.

Why a dedicated Mac mini?

A stable always-on runtime, a predictable environment, and a smaller blast radius than your daily computer.
